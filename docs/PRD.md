## 1. 项目定位



* 一款 **开源（MIT）、对标 VOFA+ 核心体验** 的 C++ / Qt6 串口调试工具，产品名 **GayoSpace**。

### 1.1 项目动机（Grayson，2026-11-16）



* 本项目非一时兴起：长期没有找到适合自己的串口工具，此前调试 PID 等场景**连看波形的工具都没有**。

* VOFA+ 体验不错但**收费**，这是坚定自研的直接原因。

* **近期有一个 PID 项目需要用本工具调试**——PID 调参（多通道实时波形 + 不卡顿不丢帧 + 暂停 / 缩放分析）是**首要使用场景**，波形体验（F-05）与数据引擎（F-03）的优先级高于其他一切功能；TS 阶段的性能取舍一律以 "PID 调参场景流畅" 为第一准绳。

* **平台策略**：v1.0 只在 Windows 上发布与测试，但**跨平台是确定性的后续需求**（Grayson 在 macOS / Linux 环境下有开发场景）—— 因此架构上从第一行代码起就禁止平台锁死，见第 5 节非功能需求。

* **CLI 是硬性需求**：除 GUI 外必须提供 CLI 运行形态，为 Agent / 脚本化操作留出可编程空间（见 F-07）。

* 核心价值主张：**"串口收发 + 数据引擎 + 实时波形" 三件套做到流畅、准确、不卡顿**，让嵌入式工程师不装 VOFA+ 也能完成日常调试。

* 与 VOFA+ 的差异点（不承诺 v1.0 实现）：开源、MIT 许可、脚本协议解析无生态门槛。

* 目标用户：嵌入式 / 单片机开发者（自用 + GitHub/Gitee 社区）。

* 参考项目：xTools、serial\_debug\_tool（Qt 路线精读对象，见《串口工具开源项目参考清单.md》）。

## 2. 需求分级

### 2.1 本期做（In Scope，v1.0）



| 编号   | 需求       | 说明                                                                                                                                                                            |
| ---- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| F-01 | 串口基础收发   | 端口扫描与热插拔检测；波特率 / 数据位 / 停止位 / 校验位 / 流控配置；打开 / 关闭 / 自动重连；Text 与 Hex 双模式收发；发送历史与快捷发送；定时发送（周期可设）                                                                                  |
| F-02 | 收发辅助     | 收发字节统计（RX/TX 计数）；接收区时间戳（可选开关）；接收区暂停 / 清空；接收日志保存到文件                                                                                                                            |
| F-03 | 数据引擎     | 内置协议：**JustFloat**（小端 float 数组 + 帧尾 00 00 80 7F，无帧头靠帧尾切帧；已按 VOFA+ 官方文档核对，出处见 TS-SW 第 4.1 节）、**FireWater**（逗号分隔 ASCII + 换行结尾，同上已核对，出处见 TS-SW 第 4.2 节）；解析结果输出为 "通道号 → 数值" 序列                                           |
| F-04 | 自定义脚本协议  | 内置 JS 脚本引擎（QJSEngine）：用户编写脚本将原始字节流解析为通道数值；提供脚本编辑、错误提示、示例脚本；**仅限协议解析用途**（见 2.2 TODO-001）                                                                                       |
| F-05 | 实时波形     | 多通道实时曲线（目标 ≥8 通道 @ ≥1kHz 单通道采样率不丢帧，具体性能指标在 TS 中分配）；缩放 / 平移 / 自适应；暂停 / 恢复绘制；通道显示开关与颜色区分                                                                                        |
| F-06 | 会话配置     | 串口参数与协议选择的会话记忆（本地配置文件，重开软件恢复上次状态）                                                                                                                                             |
| F-07 | CLI 运行形态 | 提供 headless CLI（GUI 与核心逻辑分层是前提，见 5 节）：命令行指定串口参数与数据协议，完成收发与数据采集，结果以结构化格式输出（JSON / CSV 落盘或 stdout）；错误码可被脚本判定。v1.0 覆盖 "打开串口 → 收数 → 按协议解析 → 落盘" 与单次发送两类场景，完整 Agent 深度集成见 TODO-008 |

## 4. 安全与失效模式表

> 本产品为非加热类桌面工具，失效后果为 "数据丢失 / 界面假死 / 误发数据"，不涉及人身安全。硬件兜底不适用，软件行为即全部承诺。



| 失效点      | 触发条件                 | 期望行为（软件动作）                              | 用户可见提示                   | 双重保护                 |
| -------- | -------------------- | --------------------------------------- | ------------------------ | -------------------- |
| 串口意外断开   | 拔线 / 设备重启 / 被其他程序抢占  | 停止收发，进入重连流程（自动重连开关开启时），数据通道置无效          | 状态栏红显 "已断开"+ 断开原因        | 自动重连失败计数上限，避免无限刷     |
| 接收缓冲区暴涨  | 高波特率连续灌数且解析阻塞        | 环形缓冲丢弃最旧数据并计数，绝不阻塞 UI 线程                | 丢弃计数提示 "RX 丢帧 N 字节"      | 解析线程与 UI 线程分离（TS 细化） |
| 异常 / 残缺帧 | JustFloat 帧尾错位、脚本抛异常 | 丢弃该帧，字节流重新同步；脚本异常捕获不崩溃                  | 状态栏显示 "解析错误" 计数；脚本错误显示行号 | 脚本执行超时强制中断（TS 定阈值）   |
| 波形绘制过载   | 通道数 × 频率超出绘制能力       | 数据按策略降采样 / 抽稀，界面保持可操作                   | 提示 "当前负载超出实时绘制能力"        | 用户可关闭部分通道减负          |
| 误发送      | 定时发送误开启、Hex 模式输入非法字符 | Hex 输入实时校验非法字符；定时发送有醒目运行标识              | 非法字符红显且拒绝发送              | 发送前格式二次校验            |
| 日志文件写入失败 | 磁盘满 / 文件被占用          | 停止写入并保留内存缓冲，不崩溃                         | 弹窗提示写入失败及原因              | —                    |
| 软件崩溃     | 未捕获异常 / 系统级故障        | 崩溃时生成含版本信息的错误转储文件，下次启动提示上报途径（仅提示，不自动上传） | 启动时提示 "上次异常退出"           | —                    |
