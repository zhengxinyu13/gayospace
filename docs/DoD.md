## 2. 测试门槛

### 2.1 框架与流程（AGENTS.md 第二节硬要求）

- 测试框架先于业务代码搭建，选型（Qt Test / Catch2 / GoogleTest）在 TS 定。
- 每个新需求进入时同步新增对应测试；交付前 100% 通过，红一个不许发版。

### 2.2 必测场景

| 类别 | 必测项 |
| --- | --- |
| 协议引擎单元测试 | JustFloat：标准帧、残帧、粘帧、帧尾错位重同步；FireWater：正常流、非法分隔、半行截断；脚本协议：正常解析、脚本异常、超时中断 |
| 串口层 | 开关、参数全组合枚举、意外拔出、自动重连、热插拔事件 |
| 数据管道 | 环形缓冲满载丢弃计数、高负载不阻塞 UI、暂停/恢复 |
| CLI | 参数解析、JSON/CSV 输出正确性、退出码契约（成功/参数错/串口错/协议错分类） |
| 失效模式 | PRD 第 4 节表格逐行至少 1 条自动化或手工用例 |
| 会话配置 | 保存/恢复/损坏配置文件的容错 |

### 2.3 覆盖率与性能基准

- 核心层（协议引擎 + 数据管道，无 UI 依赖）单元测试行覆盖率 ≥ 80%，用覆盖率工具实测后写入测试报告。
- 性能基准（对应 PRD F-05 指标，具体数值 TS 分配）：8 通道 × 1kHz 持续灌数 10 分钟，UI 不卡顿、无丢帧，CPU/内存占用记录实测值。
- 核心层测试必须能在无 GUI 的 CI 环境（headless）独立运行——这是分层目标的验收探针。

### 2.4 HIL

不适用（无硬件在环）。以"本机 + USB 转串口对捞（两个真实端口互发）"替代真机链路测试。

## 4. 验收方式

- **验收人**：Grayson。
- **验收场景（什么算通过）**：用近期 PID 项目的真实设备跑一次完整调参流程——配串口 → 采集 ≥4 通道 → 波形实时观察 → 暂停/缩放定位细节 → CLI 后台采集落盘。全流程无卡顿、无丢帧、无崩溃，即视为核心验收通过。
- **回归口径**：GitHub CI（或本地脚本）全绿 + 测试报告数据达标 + 上述真实场景验收通过，三者齐备才算 v1.0 达成 DoD。
- 未达成项逐条显式列出于 Release notes，不得静默降级。
