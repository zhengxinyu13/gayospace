## 2. 测试门槛

### 2.1 框架与流程（AGENTS.md 第二节硬要求）

- **测试框架选型是编码启动的硬前置**：Qt Test / Catch2 / GoogleTest 的选型必须在 TS 中定稿，且框架工程（含 CI 接入）先于第一行业务代码合入。PRD 定稿不得直接跳入编码。
- 每个新需求进入时同步新增对应测试；交付前 100% 通过，红一个不许发版。
- **Flaky 用例规则**：第 2.2 节必测场景中的用例不允许存在 flaky，出现即视为阻塞项必须修复；必测场景之外的用例如确认 flaky，可显式隔离（quarantine）发布，但必须同时满足四点：①登记 issue 并标注用例名；②**隔离须经 Grayson 确认，开发侧不得自行决定**；③写入 Release notes 已知问题；④下个版本必须修复或删除。禁止静默跳过。

### 2.2 必测场景

| 类别 | 必测项 |
| --- | --- |
| 协议引擎单元测试 | JustFloat：标准帧、残帧、粘帧、帧尾错位重同步；FireWater：正常流、非法分隔、半行截断；脚本协议：正常解析、脚本异常、超时中断 |
| 串口层 | 开关、参数全组合枚举、意外拔出、自动重连、热插拔事件 |
| 数据管道 | 环形缓冲满载丢弃计数、高负载不阻塞 UI、暂停/恢复 |
| CLI | 参数解析、JSON/CSV 输出正确性、退出码契约（成功/参数错/串口错/协议错分类） |
| 失效模式 | PRD 第 4 节表格逐行至少 1 条用例；覆盖方式与可模拟性要求见 2.4 |
| 会话配置 | 保存/恢复/损坏配置文件的容错 |

### 2.3 覆盖率、性能基准与静态约束

- **核心层边界在 TS 中锁定**：TS 必须显式列出纳入覆盖率统计的源码目录清单（协议引擎、数据管道必含；串口层、会话配置是否纳入由 TS 论证后定），覆盖率分母以该清单为准，不得随实现漂移。核心层单元测试行覆盖率 ≥ 80%（基准线，可在 TS 定稿时调整），用覆盖率工具实测后写入测试报告。
- **性能基准（对应 PRD F-05，具体数值 TS 分配后锁定）**：8 通道 × 1kHz 持续灌数 10 分钟，组合判据：①环形缓冲丢弃计数为 0（客观）；②UI 事件循环延迟 P99 < 50ms（客观，阈值 TS 可校准）；③CPU/内存占用记录实测值。"不卡顿"不再作为独立判据出现。**P99 阈值校准方法：TS 校准时须以真实 PID 调参场景做一次感知验证（Grayson 参与操作与评价），据此决定维持或收紧 50ms，不凭经验拍板。**
- **跨平台约束静态检查（对应 PRD 第 5 节硬约束）**：CI 中加入扫描规则——业务代码目录（TS 划定，排除显式许可的平台层目录）不得出现 Win32 专属头文件与 API 符号（初始符号表由 TS 定义）。扫描不通过 = CI 红 = 不许合并。**符号表维护机制：任何平台专属调用的新增/变更，必须先在平台层立项并同步更新符号表与扫描规则（与 AGENTS.md 变更管理同流程），防止符号表随时间腐化；该机制在 TS 中落为正式章节。**
- **UI 合规字符串检查**：CI 中检查含 UI 的源文件必须包含字符串 `This software was written by Grayson Zheng.`，缺失即 CI 红。
- 核心层测试必须能在无 GUI 的 CI 环境（headless）独立运行——这是分层目标的验收探针。

### 2.4 失效模式用例的覆盖方式标注

- 测试报告中，PRD 第 4 节失效模式表逐行标注：**自动化 / 手工**；手工用例必须写明操作步骤且可重复执行。
- 依赖特定物理状态的用例必须给出可模拟替代方案并落地，例如"磁盘满"用容量受限的虚拟盘（RAM disk / VHD 配额）模拟，不依赖真实写满一块盘。

## 4. 验收方式

### 4.1 验收人

Grayson。

### 4.2 核心验收场景

用近期 PID 项目的真实设备跑一次完整调参流程——配串口 → 采集 ≥4 通道 → 波形实时观察 → 暂停/缩放定位细节 → CLI 后台采集落盘。全流程满足 2.3 组合判据（丢弃计数 0 + P99 < 50ms）且无崩溃。

**可复现口径**：真实场景不可复现（依赖特定设备），因此测试报告必须同时包含 2.5 两端口对捞的模拟负载基准数据（可复现），两者互为背书——真实场景验体验，模拟基准验指标。

### 4.3 发布形态验收

便携 zip（v1.0 唯一发布形态）逐项验收：

- 便携包：在**无安装环境**（干净目录、无管理员权限）解压即可运行；不写入注册表与系统目录（解压目录外零写入）。
- Release 附件齐全：按第 1 节交付物清单核对，缺一即不达 DoD。

### 4.4 回归口径

GitHub CI（或本地脚本）全绿 + 测试报告数据达标（覆盖率、性能组合判据、静态扫描）+ 4.2 真实场景验收通过 + 4.3 发布形态验收通过，四者齐备才算 v1.0 达成 DoD。未达成项逐条显式列出于 Release notes，不得静默降级。
